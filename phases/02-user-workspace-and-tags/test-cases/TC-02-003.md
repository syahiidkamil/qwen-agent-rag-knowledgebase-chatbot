# TC-02-003: Invalid tag inputs surface inline without dismissing the dialog

## Type
edge-case

## Preconditions
- Seeded admin account exists.
- At least one ingested document is in the knowledge base.

## Steps
1. Sign in as admin; open the Edit document dialog on an ingested row.
2. Attempt to add each of the following tags one at a time:
   - A tag with 50 characters (over the 32-char limit).
   - A tag containing a forward slash (e.g. `cat/sub`).
   - 17 short tags in succession (one over the 16-tag cap).
3. Observe the dialog after each invalid input.

## Expected Result
- Over-length tag: inline error reads "Each tag must be 32 characters or fewer." The chip is NOT added.
- Path-separator tag: inline error reads "Tags cannot contain path separators or null bytes." The chip is NOT added.
- 17th tag attempt: inline error reads "At most 16 tags per document." The 17th chip is NOT added.
- The dialog stays open in every case; existing valid chips remain. The user can correct the bad input and continue without losing work.
- If the FE client-side guard is somehow bypassed and a bad request reaches the backend, the backend returns 400 `INVALID_TAGS` with a specific message, and the dialog surfaces it inline via the same error path (verified end-to-end via DevTools network replay).

## Priority
medium
