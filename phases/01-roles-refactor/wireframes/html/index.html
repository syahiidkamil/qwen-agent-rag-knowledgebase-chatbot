Phase 01: roles-refactor

Low-fidelity wireframes for every user-facing surface this phase touches. Click a card to view that screen's structure, states, and notes.

Screens

1 · Modified Login Single sign-in for every role. Role-based redirect after success. 2 · Modified Admin shell Sidebar visibility per role. super_admin sees Landing; admin doesn't; user is redirected. 3 · Modified Knowledge base (admin) Existing page + new Rename action and dialog. 4 · New User workspace · /workspace Read-only KB list + auto-opened wider chat panel. Minimizable. 5 · New Users List, create, deactivate. No password reset, no email invitation. 6 · Modified Landing config (super_admin only) Chat-mode toggle + brand presets. One save covers both. 7 · Modified Public landing — chat widget states Public-mode chat or "Sign in to chat" gate when internal-mode + anonymous.
Reading order suggestion: Login → Admin shell → Knowledge base (admin) → Users → Landing config → Public landing widget → User workspace. That order roughly follows the implementation roadmap (auth/role infra first, super-admin controls next, end-user surface last).
These are wireframes, not designs. Dashed borders, system fonts, no color theming — the point is structure. Implementation can deviate visually as long as the structure, state coverage, and interaction model match.
