Interactions

  • [+ Add user] → open dialog.
  • [Create user] → POST /api/users with {email, password, role}. On 200: dialog swaps to post-create. On 4xx: inline error.
  • [Deactivate] → PATCH /api/users/{id}/deactivate. No confirmation (reversible).
  • [Reactivate] → PATCH /api/users/{id}/reactivate.
  • Email non-editable after creation.

Notes

  • Admin AND super_admin can both create users of any role.
  • "Deactivate" = Supabase Auth banned_until set far in the future. "Reactivate" clears it.
  • Already-issued JWTs stay valid until expiry (~1h); documented accepted limitation.
  • No pagination this phase — list expected < 50 users.
  • All actions require require_role("admin") on the backend (admin + super_admin pass).
