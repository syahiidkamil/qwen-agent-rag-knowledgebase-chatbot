# TC-01-002: User signs in and completes a chat turn

## Type
happy-path

## Preconditions
- Seeded user account exists and is active.
- The knowledge base contains at least one ingested document (e.g. the seeded sample PDF) so that retrieval has something to return.
- Chat mode is `internal` (or `public` — this test works either way for an authenticated user).

## Steps
1. Sign in at `/login` with the seeded user credentials.
2. Land on the internal chat surface.
3. Type a question that should hit the seeded document (e.g. "When does cohort 14 start?").
4. Submit and wait for the streamed response to complete.
5. Inspect the response and the source chips.

## Expected Result
- The chat surface renders with the Aira intro and an input field.
- The submitted message appears in the conversation.
- A streamed answer arrives token-by-token and finishes within ~5 seconds (with `qwen-plus-latest`).
- At least one source chip is rendered, referencing a real document from the corpus.
- The browser network panel shows `POST /api/chat` returning 200 (not 401, not 403).

## Priority
critical
