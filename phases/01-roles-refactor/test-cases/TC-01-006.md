# TC-01-006: Super-admin toggles chat mode to internal; anonymous visitor sees sign-in prompt

## Type
happy-path

## Preconditions
- Seeded super-admin account exists.
- Chat mode is currently `public` (default).
- A second browser (or incognito window) is available to act as an anonymous visitor.

## Steps
1. In browser A, sign in as super-admin and navigate to the Landing config / Chat mode toggle.
2. Confirm the toggle currently shows `Public`.
3. In browser B (anonymous), navigate to the landing page and confirm the chat widget is visible and usable.
4. In browser A, flip the toggle to `Internal` and save.
5. In browser B, refresh the landing page.
6. Attempt to send a chat message from browser B.

## Expected Result
- The toggle in browser A saves successfully (success toast or visible state change).
- After refresh in browser B, the chat widget shows a "Sign in to chat" prompt instead of the input field.
- If browser B somehow submits a chat request directly (e.g. via DevTools), the backend returns 401.
- Switching the toggle back to `Public` in browser A and refreshing browser B restores the chat widget for the anonymous visitor.

## Priority
critical
