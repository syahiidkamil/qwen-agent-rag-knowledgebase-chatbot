# TC-01-003: Admin renames a knowledge-base document via the Edit dialog

## Type
happy-path

> **Phase 02 update**: The Rename action and Rename dialog were renamed to **Edit document** in Phase 02; the same dialog now also edits tags (covered separately in [TC-02-002](../../02-user-workspace-and-tags/test-cases/TC-02-002.md)). This TC continues to cover the filename-rename happy path only — same backend endpoint, same source-chip propagation guarantees.

## Preconditions
- Seeded admin account exists and is active.
- At least one document is ingested and visible in the documents list.

## Steps
1. Sign in as admin and navigate to the Knowledge base page.
2. Locate a row for an ingested document; click the **Edit document** action (pencil icon).
3. In the Edit document dialog, replace the filename with a new value (e.g. append "-renamed"). Leave the tags field untouched.
4. Click Save.
5. Observe the document list refresh.
6. Sign out and sign in as a user; ask a question that retrieves this document.
7. Inspect the source chip on the assistant response.

## Expected Result
- The Edit document dialog opens with the current filename pre-filled and the basename portion pre-selected. The tags field renders existing tags (if any) as chips and an empty input below them.
- After saving, the document row in the list shows the new filename. The Save button stays disabled when no field has changed.
- The source chip on a future chat answer displays the new filename, not the old one.
- The Storage object is unchanged (the document is still downloadable from its original `storage_path` if anyone checks).
- No new ingestion is triggered; chunk count is unchanged.

## Priority
high
