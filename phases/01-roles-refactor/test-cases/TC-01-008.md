# TC-01-008: User role cannot reach admin endpoints (security regression of the closed hole)

## Type
edge-case

## Preconditions
- Seeded user account exists and is active.
- The seeded user can sign in successfully.

## Steps
1. Sign in as the seeded user; capture the Bearer JWT from the session (e.g. via browser devtools → local storage / network panel on an authenticated request).
2. Using `curl` (or DevTools network tab "replay"), make the following requests with the user's Bearer token:
   - `GET /api/documents`
   - `POST /api/documents` (with a small dummy file body)
   - `DELETE /api/documents/{any-id}`
   - `GET /api/users` (assuming the new endpoint)
   - `POST /api/users` (assuming the new endpoint)
   - `PUT /api/landing-config`
3. In the FE, manually type `/admin` (or whichever admin URL exists) into the address bar.

## Expected Result
- Every admin API request returns HTTP 403 with a structured error body (not 200, not 500, not 401).
- The FE admin URL redirects to the internal chat surface (or shows a "you don't have permission" message).
- None of the requests succeed in mutating or reading admin-only data.

## Priority
critical
