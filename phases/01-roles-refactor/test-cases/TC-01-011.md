# TC-01-011: Existing public chat continues to work (regression)

## Type
regression

## Preconditions
- Chat mode is `public` (default, or set explicitly).
- The knowledge base contains at least one ingested document.
- No user is signed in; anonymous browser session.

## Steps
1. In an incognito browser, navigate to the landing page.
2. Observe the chat widget.
3. Submit a question that should hit the seeded document.
4. Wait for the streamed response.

## Expected Result
- The chat widget is visible without any sign-in prompt.
- The submitted question receives a streamed answer (same flow as before this phase).
- At least one source chip renders.
- `POST /api/chat` returns 200 with no Authorization header sent.
- The conversation persists across the session (the existing session_id flow remains intact).

## Priority
critical
